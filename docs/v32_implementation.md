# CRU-Harness V3.2 技术实现

V3.2 将完整来源空间、有界模型工作空间与持续事实状态分开管理。
模型进行必要的局部语义判断，本地软件持有原文和索引、累积事实并确定性计算。
最新实测来源最高 1,866,427 Qwen tokens，达到服务报告原生上限的 7.12 倍。
完整得分与容量口径见 [最新评测](benchmark_v32.md)。

## 执行入口和类型化计划

[`harness.py`](../long_context_agent/harness.py) 提供执行入口，
[`adaptive_evidence_v3.py`](../long_context_agent/adaptive_evidence_v3.py) 组织查询规划、分类、追检和结算。
完整提示可容纳时直通模型；超预算来源按记录或原文窗口处理。
计划把来源范围、分类字段、语义过滤、分组键和归约操作分开。

`conditional_group` 支持标签筛选、按源用户或日期分组、计数、argmax/argmin。
用户与日期是已解析的源字段，语义类别由模型提供；未知和冲突保留在状态中。
模型不必在最后一次提示中重新读入全部已取得事实。

## 来源绑定事实与确定性聚合

[`record_protocol.py`](../long_context_agent/record_protocol.py) 使用短 alias 与标签索引传输分类结果，
本地绑定真实记录身份、正文跨度和来源哈希。无效索引和重复别名被拒绝，缺失只影响对应记录。
[`fact_ledger.py`](../long_context_agent/fact_ledger.py) 持续保存接纳事实、冲突和未知量。
同一物理记录的重复提交不重复计数，不同物理实例保留真实重数。

count、频率比较、日期极值、分组统计与联合归约由程序执行。
各组保留已知计数下界及包含未知量的上界；只有候选下界严格超过全部竞争组上界，才可提前确定唯一赢家。
算术闭合依赖查询范围和已接纳标签正确，不能替代语义标签的独立验证。

## 完整正文等价复用

[`semantic_coverage.py`](../long_context_agent/semantic_coverage.py) 按完整字符串相等组织正文等价类。
一次代表分类可以回填给多个物理实例，并保留每个实例的用户、日期、来源跨度和重数。
哈希用于审计，不单独作为正文相等的判断依据；不做模糊或近似语义合并。

最新运行核验 47,202 条等价转移与 52,839 条保留来源记录。
复用依赖当前标签只由完整投影正文决定；代表分类错误可能随重数放大。
当标签依赖用户、日期或跨记录上下文时，通过 `exact_body_coalescing=False` 关闭复用。

## 有界追检与完整状态

记录和同文组共享最多两次尝试，连续两轮无新增有效事实则停止。
重复副本不能绕过尝试上限。结构化路径从完整账本结算；叙事路径为最终生成预留预算，
不静默裁掉已经接纳的引文事实。无收益停止保证控制流有界，但关键未知仍需不同裁决策略。

## 统一预算和审计

[`experiment_budget.py`](../long_context_agent/experiment_budget.py) 将所有生成计入同一任务账本，
服务 tokenizer 检查单次输入加输出准入，provider usage 记录实际成本。
分类、修复、递归、摘要和最终回答没有独立的隐藏配额。

最新 V3.2 的 12 题共 113 次生成、310,311 个输入输出 tokens，用量全部已知、均未越界。
12/12 机制结果通过来源、传播与事实保留检查。
独立重放覆盖 100 次分类响应、5,931 个正文绑定、47,202 条转移以及最终聚合。
相关工程回归在实验前通过 372 项，README 的便携核心检查覆盖其中 76 项。

## 当前研发重点

最新三类未满分问题分别涉及全局语义分类与标注一致性、无重复正文下的候选组预算调度、关键 null 裁决。
改进以当前 V3.2 为基线，在新来源上冻结代码、预算与样本后统一评分。
源空间扩展、计算闭合和答案准确性分别计量。
